# Defense Duell — integration contract / Core v1.8

Date: 2026-11-10. C# 9 / .NET Standard 2.1. Three 1600×960 maps, two players, four combat tower classes plus a goldmine, 20 Hz authoritative ticks, 8-minute play limit (9600 ticks), 60-tick countdown. Genuine 3D rendering, no physics simulation. Host and bot commands enter the same validation method. Player identities and render capacity slots are independent of NGO client IDs.

## Additions approved during implementation

- Combat towers and mines both use continuous map coordinates on `FreePlacement=true` maps. Maximum thirty combat towers and two freely placed mines per player; internal `TowerState.Slot` is render capacity only. No mine sites remain reserved.
- `ErrorCode.ClassLimit`, `OutsideMap`, `OnPath`, `BlockedArea`, `TooClose` are appended, ending at value20. Goldmine remains kind4; original combat and troop indices are unchanged.
- Goldmine income 1/2/3 per second; costs 140/100/160. Mines use the same terrain, path, edge and building-separation checks as combat towers and never attack.
- Combat towers have at most two paid upgrade purchases in total, choosing Damage or Range each time. Mines keep their two Income purchases. The first/second purchase prices remain unchanged; the selected path changes only its own statistic, with base fire interval preserved.
- Beta economy: start180, passive5 gold/s, max10000, kill rewards4/5/14/2 paid once to the defender. Speeds104/184/59/93. See `Docs/EconomyIteration.md` for the explicitly separate v1.5 slot-map experiments and limitations.
- Every troop tap buys immediately. Paid FIFO capacity80/player. Class cooldown begins on a group's first actual spawn; `NextSendTicks` is an earliest departure time, not a purchase lock. Full fields retain paid troops. Global/intra-swarm spawn interval4 ticks remains unchanged.
- `MapDefinition` includes dimensions, legacy mine indices, free-placement flag and rectangular blocked areas. Free maps require an empty MineSlots array; legacy mixed or dedicated slots remain valid. Every definition, bound and placement constant participates in the content hash. `MapCatalog.Count=3`, `Create(index)`, `CreateContents(template)` retain map0 from the template. Themes meadow/desert/frost.
- `UnitState.MovementRemainder` preserves fractional movement at the fixed tick rate.
- `SetSpeedVote` records each player's explicit 1x/2x consent. The computed SimulationSpeed is2 only during Playing with both votes; accepting either withdrawal restores1 immediately. Each Core Step still advances exactly one game-time tick. Countdown/results remain1x and rematches clear both votes.
- `SessionCoordinator.Initialize(GameContent[])`, `MapNames`, `SelectedMapIndex`, `CatalogHash`, `SelectMap(index)` support menu-only map selection. Approval checks the ordered complete catalog. Welcome carries the host map index and snapshot revision; client adopts content before decoding.
- Protocol version is4; older clients cannot join. Position-bearing commands and upgrade-path snapshots are described in the networking section below.
- Presentation is `BoardView` with real low-poly meshes, isolated tilted cameras/RenderTextures, pooled units/effects and projected touch targets. Close targets use nearest-centre hit filtering. GameUI caches changed host content before rebuilding boards.

## Core public API (namespace DefenseDuell.Core)
- `enum PlayerSlot : byte { Zero, One }`
- `enum MatchPhase { Lobby, Countdown, Playing, Finished, Aborted }`
- `enum MatchOutcome { None, Player0, Player1, Draw, Aborted }`
- `enum CommandType { BuildTower, UpgradeTower, SellTower, SendUnit, SetReady, RequestRematch, SetSpeedVote }` (SetSpeedVote appended as6).
- `enum ErrorCode { None, WrongSession, Duplicate, StaleSequence, InvalidPlayer, WrongPhase, InvalidKind, InvalidTarget, NotOwner, Occupied, InsufficientGold, MaxLevel, Cooldown, QueueFull, RateLimited, InvalidValue, ClassLimit, OutsideMap, OnPath, BlockedArea, TooClose }` (values0..20; Cooldown retained for compatibility).
- `[Serializable] struct CommandEnvelope` fields `ulong SessionId, Sequence; CommandType Type; int Kind, Target, PositionX, PositionY;` (`SetReady` sets ready; never toggles). Coordinate fields participate in exact idempotent payload equality.
- `[Serializable] struct CommandResult` fields `ulong Sequence; ErrorCode Code; int Tick;` computed `bool Accepted => Code == ErrorCode.None`.
- `[Serializable] class MatchState` fields `ulong SessionId; uint Seed; int Tick, PlayTicks, CountdownRemaining; MatchPhase Phase; MatchOutcome Outcome; PlayerState[] Players; List<TowerState> Towers; List<UnitState> Units; List<SpawnOrder> SpawnOrders;`. Readonly computed `int SimulationSpeed` is2 only during Playing with both initialized players' SpeedReady=true, otherwise1.
- `PlayerState` fields `int Gold, Hp; bool Ready, Rematch, SpeedReady; int[] NextSendTicks;`.
- `TowerState` fields `int Id, Slot, Kind, Level, CooldownTicks, Invested, DamageLevel, RangeLevel; int SiteId=-1; MapPoint Position; PlayerSlot Owner;`. Every free-map building has SiteId=-1, including mines. Legacy fixed maps have Slot=SiteId. Free maps allocate Slot0..31 independently of position. Combat range uses actual Position. Combat Level equals DamageLevel+RangeLevel and is 0..2; mines have both path fields zero and Level is their Income stage.
- `UnitState` fields `int Id, Kind, Hp, Distance, SlowPermille, SlowUntilTick, MovementRemainder; PlayerSlot Defender;`.
- `SpawnOrder` fields `int Kind, Remaining, NextTick; PlayerSlot Sender;`.
- `struct MapPoint` with public `int X, Y`, constructor `(int x,int y)`. Distances, speeds, bounds and ranges use integer logical map units. `readonly struct MapRectangle(int minX,int minY,int maxX,int maxY)` exposes MinX/MinY/MaxX/MaxY.
- `GameContent.CreateDefault()` returns validated definitions; `string ContentHash { get; }`; `TowerDefinition[] Towers`, `UnitDefinition[] Units`, `MapDefinition Map`, `int TickRate, StartGold, BaseHp, PassiveGoldPerSecond, MaxUnitsPerField, MaxSpawnOrdersPerPlayer, MatchDurationTicks, CountdownTicks, SellRefundPercent`.
- Tower definition immutable properties `string Name; int Price, Range, Damage, FireIntervalTicks, SplashRadius, SlowPermille, SlowDurationTicks, ArmorPiercing, IncomePerSecond, MaxPerPlayer; bool IsEconomy; UpgradeDefinition[] Upgrades` (two upgrades). Constructor trailing `int incomePerSecond=0,int maxPerPlayer=32`; economy max2.
- Upgrade definition `int Price, Damage, Range, FireIntervalTicks, IncomePerSecond`, trailing constructor `int incomePerSecond=0`. Price is indexed by total previous purchases; combat Damage and Range values are independently indexed by their own path level. Both paths strictly increase; FireIntervalTicks must equal the base interval. Income remains a linear mine-only path.
- Unit definition `string Name; int Price, Hp, SpeedPerSecond, Armor, BaseDamage, Count, CooldownTicks, KillBounty`, constructor trailing `int killBounty=0`.
- Map constructor `MapDefinition(MapPoint[] waypoints, MapPoint[] buildSlots, string id="meadow", string name="Grünes Tal", int theme=0, int width=1000, int height=600, int[] mineSlots=null, bool freePlacement=false, MapRectangle[] blockedAreas=null)`. Public immutable metadata Id/Name/Theme/Width/Height/Length/FreePlacement; copied arrays Waypoints/BuildSlots/MineSlots/BlockedAreas; `HasDedicatedMineSlots`, `IsMineSlot(int)`, `CanBuildAt(int slot,bool economy)`, `PositionAt(int distance)`. Free maps must use null/empty MineSlots. Legacy maps allow mixed slots or exactly two unique dedicated mine indices. BuildSlots remain legacy coordinates and optional bot hints; they never constrain free human building coordinates.
- `MatchSimulation(GameContent content, uint seed = 1, ulong sessionId = 1)`, `MatchState State { get; }`, `CommandResult Execute(PlayerSlot sender, CommandEnvelope command)`, `void Step()`, `void Abort()`. `GameContent Content { get; }`.
- `BotBrain(PlayerSlot slot, uint seed = 1)`, `void Tick(MatchSimulation simulation)`. Must use Execute and account for own sequence/session. Bot acts in Playing only and never independently sets Ready, Rematch or SpeedReady; offline coordinator owns those explicit mirrors.
- `GameContent.Validate()` throws for invalid definitions. Additional core fields/methods allowed without breaking API. Hash must cover every gameplay rule, not just names. Definition collections are copied into each match; never mutate definitions during play.

## Shared placement contract

- `PlacementValidator` exposes constants `BuildingRadius=30`, `PathClearance=70`, `BuildingSeparation=60`, `CombatCapacity=30`, `MineCapacity=2`, `RenderCapacity=32`.
- `ValidateBuild(GameContent content, MatchState state, PlayerSlot owner, int kind, int target, MapPoint requested, out TowerPlacement placement) -> ErrorCode` performs phase, kind, geometry, capacity and gold checks without mutating state. `TowerPlacement` readonly properties Position/Slot/SiteId describe the authoritative resolved placement.
- `ValidatePosition(GameContent content, MatchState state, PlayerSlot owner, int kind, int siteId, MapPoint position, int ignoredTowerId=-1) -> ErrorCode` performs geometry/site checks only. It does not depend on gold, phase or purchase capacity. Snapshot validation passes the inspected entity's ID to avoid self-collision. Opponent buildings never block a player's board.
- Every free-map BuildTower command, including a mine: Target=-1 and PositionX/PositionY are actual desired coordinates. Reject outside footprint bounds, path-centre distance<70, blocker overlap or own-building centre distance<60. No snapping and no reserved mine areas. Exact allowed boundaries remain valid.
- Only legacy fixed maps use Target for a fixed build location and resolve coordinates from definitions. Occupied legacy sites are rejected. Geometry rejection never spends gold. Maximum free-map counts remain thirty combat towers and two mines.
- Placement errors: OutsideMap17, OnPath18, BlockedArea19, TooClose20. InvalidTarget covers incompatible site/category or incorrect fixed coordinates; Occupied covers an occupied fixed site. ClassLimit covers per-class/capacity limits.
- Hash includes dimensions, legacy mine indices, free-placement flag, blocker bounds, placement/upgrade constants and explicit rule version `defense-duell-core-v1.8`.

## Shared upgrade contract

- `enum TowerUpgradePath : byte { Damage=0, Range=1, Income=2 }`. UpgradeTower.Target is the tower entity ID; UpgradeTower.Kind is the chosen path. Build/Send meanings of Kind do not change. Position fields never move an upgraded building.
- `readonly struct TowerStats` properties: `int Damage, Range, FireIntervalTicks, IncomePerSecond`.
- `readonly struct UpgradeQuote` properties: `ErrorCode Code`, `bool IsValid`, `TowerUpgradePath Path`, `int Price`, `TowerStats Current, Next`, `int NextLevel, NextDamageLevel, NextRangeLevel`.
- `TowerUpgradeRules.Quote(GameContent content, TowerState tower, TowerUpgradePath path) -> UpgradeQuote` is pure and does not check gold, ownership or match phase. UI can display unaffordable values. Unsupported/invalid paths return InvalidKind; inconsistent tower levels return InvalidValue; a third legal-path purchase returns MaxLevel.
- `TowerUpgradeRules.Stats(GameContent content, TowerState tower) -> TowerStats` is the common actual-stat source. Damage uses DamageLevel, range uses RangeLevel, fire interval stays at the base value; mine income uses Level.
- `TowerUpgradeRules.ValidateState(GameContent content, TowerState tower) -> ErrorCode` checks only kind and path/total-level invariants. Investment, ownership, phase and money checks remain at their existing boundaries. Stats throws ArgumentException for invalid tower state; validate incoming snapshots first.
- `TowerUpgradeRules.VisualVariant(TowerState tower) -> int`: combat variants `(DamageLevel,RangeLevel)` = `(0,0):0`, `(1,0):1`, `(0,1):2`, `(2,0):3`, `(1,1):4`, `(0,2):5`. Formula is Level*(Level+1)/2+RangeLevel. Mine kind4 uses its Level0..2. Invalid combinations throw ArgumentException.
- `TowerUpgradeRules.MaxPurchases=2`. Execute checks owner, phase, legal path and gold before changing anything. It atomically applies quote Price and next levels, increments Invested, and preserves cooldown, actual position, IDs and footprint. Duplicate request/payload replays its original receipt; changed path under the same request ID is Duplicate.
- Explicit default Damage paths: 6/9/14, 16/26/40, 4/6/8, 40/64/96. Explicit Range paths: 150/180/210, 155/186/217, 155/186/217, 190/228/266. Base intervals: 8/32/20/42. Range I/II are ceil(base*1.2/1.4), stored in already-hashed definition fields. Prices remain 55/85, 85/130, 60/95, 85/130; mine Income prices100/160.

## Network-facing API (namespace DefenseDuell.Networking)
- `enum SessionMode { Offline, Lan, Online }`; `enum ConnectionState { Idle, Connecting, Lobby, Loading, Playing, ConnectionLost, Finished }`.
- `SessionCoordinator : MonoBehaviour` owns all lifecycle and listeners. `void Initialize(GameContent content)` delegates to `void Initialize(GameContent[] catalog)` using MapCatalog.CreateContents. The validated ordered three-map catalog is copied before use.
- Properties: `MatchState State`, `GameContent Content`, `PlayerSlot LocalSlot`, `bool IsHost`, `SessionMode Mode`, `ConnectionState Status`, `string Message`, `string JoinCode`, `int ConnectedPlayers`, `long SentBytes, ReceivedBytes`, `CommandResult LastResult`, `int SelectedMapIndex`, `string[] MapNames`, `string CatalogHash`. `bool SelectMap(int index)` is allowed only while Idle. Welcome selects the host map before client snapshot validation and raises Changed.
- Events: `event Action Changed; event Action<CommandResult> CommandResolved`.
- Methods: `void StartOffline(uint seed = 1)`, `void StartLanHost(ushort port = 7777)`, `void JoinLan(string address, ushort port = 7777)`, `Task HostOnlineAsync()`, `Task JoinOnlineAsync(string code)`, `ulong Submit(CommandType type, int kind = 0, int target = -1, int positionX = 0, int positionY = 0)`, `void Shutdown()`.
- Network object/spawn scene synchronization disabled: one local boot scene; NGO custom messages carry commands, acks, readiness/result, snapshots. No arbitrary client-provided state is applied by host. Version/catalog handshake before lobby admission (NGO connection approval payload). ProtocolVersion = 5; version 4 and older are rejected. Commands are 33 bytes and include PositionX/PositionY; UpgradeTower.Kind selects Damage0/Range1/Income2 and belongs to exact request identity. All free-map buildings, including mines, use Target/SiteId = -1 and actual coordinates.
- Tower snapshots use 30-byte records including actual Position, SiteId, DamageLevel and RangeLevel; Slot is only the render index. TowerUpgradeRules.ValidateState rejects invalid path/total-level combinations before Stats is used. Separately, Invested must exactly equal the building base price plus the prices of the first Level upgrade purchases, independent of the selected paths; any mismatch rejects the entire snapshot. Complete-board geometry is checked through PlacementValidator.ValidatePosition, plus 30 combat / 2 mine capacity, per-owner render uniqueness, and legacy Slot == SiteId. Maximum snapshot payload is 7766 bytes (9 chunks), 38830 payload bytes/second at 5 Hz. ACK codes extend through TooClose; unknown codes fail decoding.
- Use current MPS package's RelayService + AllocationUtils.ToRelayServerData(..., "dtls"), per Unity's supported manual Relay/NGO integration. No legacy standalone relay package, no Lobby dependency usage required. Initialize Services/Auth only for Online; no cloud project created automatically.
- Snapshot replication >=5 Hz. Reliable ordered actions/acks and results. Movement snapshots may be split into bounded unreliable chunks and atomically assembled with snapshot sequence if necessary; no reliable transform RPC per frame. Enforce max bytes, counts and chunk TTL. Measure traffic.
- Session id changes for each rematch; sequence resets only then. Host validates sender mapping. Local host also calls same Execute path. Ignore commands with old epoch, handle stale/duplicate replies idempotently. Rate limit before allocations. 12-second progress timeout and bounded connecting timeout; pause aborts network matches. Offline pause may freeze.
- Leave/Shutdown cancels async continuations via generation token; owns each event subscription once, no stale callbacks restarting connections. Remote disconnect aborts with no invented winner. A fresh Host/Join must work without app restart.

## Approved 0.6 speed agreement (2026-11-10)

Baseline a80c882 (verified 0.5). Core rules v1.8, existing Content schema5 (no serialized definition-field change), Wire5. Append CommandType.SetSpeedVote after RequestRematch. Command Kind=0 withdraw/normal, Kind=1 approve2x; Target=-1, PositionX=PositionY=0. Only Playing phase, strict payload validation, normal sequence/idempotency/rate validation, no gold changes. Append PlayerState.SpeedReady bool. MatchState.SimulationSpeed readonly computed property:2 only during Playing and both players' SpeedReady=true, otherwise1. New epochs/rematches start with both false. Either player can withdraw immediately; no unilateral2x.

Core error mapping: outside Playing => WrongPhase; Kind outside0/1 => InvalidKind; Target other than−1 => InvalidTarget; nonzero PositionX/PositionY => InvalidValue. Existing session/player/sequence/receipt/rate checks run first. Accepted commands only set the sending player's boolean; no costs, ticks or gameplay timers change. Duplicate receipts never reapply an old vote over newer consent, including old withdrawal receipts; rate-limited votes remain rejected on replay. A fresh accepted withdrawal changes effective speed immediately without waiting for Step.

Authority advances the unchanged20Hz game-time simulation using wall tickTime=1/(Content.TickRate*State.SimulationSpeed). Countdown stays1x. Economy, movement, combat, spawn delays and match clock all accelerate together; no Time.timeScale, no relaxed timeouts or accelerated network heartbeat. Reset accumulated wall time when effective speed changes to avoid a queued catch-up burst. Offline coordinator mirrors the local accepted speed vote through the same validated Execute path for bot slot; bot does not spontaneously vote. Online/LAN publishes both votes in snapshots and reliably sends state after accepted speed commands. Wire5 rejects Wire4; two added player booleans, strict bool validation and compatible bounds/digests/tests.

HUD owns a compact tempo control with clear1x/2x/pending/other-player-request labels and local toggle. Show authoritative votes/speed; pending command status is not consent. No speculative gameplay speed. Info and modal/pointer safeguards remain. Tests include one-vote/no acceleration, both votes/2x, unilateral withdrawal, duplicate/rejected/malformed votes, epoch reset, offline mirror and real two-peer agreement/withdrawal.
